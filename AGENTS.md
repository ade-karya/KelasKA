# Agent Guidance

Guidance for coding agents working in this repository, including the automated Codex review that runs on every non-draft pull request. The contribution workflow is in [CONTRIBUTING.md](CONTRIBUTING.md).

## Working Agreement

- Update this file (`AGENTS.md`) as part of every change. Record the durable build, test, deployment, or debugging lesson the work produced, in the relevant section below. Keep it short and actionable; do not duplicate code or CONTRIBUTING.md.
- After all work for a task is finished and verified, commit the changes and push them to `origin` on the current branch (Conventional Commit message), then report the branch, commit hash, and push result. Never leave finished work uncommitted; if the push is rejected or credentials are unavailable, say so explicitly instead of silently skipping it.

## Build and Test Resources

- `/KelasKA_Colab_Setup_v2.ipynb` snapshots the live `.env.local` + `openmaic.yml` (Gemini key, Supabase/DB, HF credentials), so it stays in `.gitignore` and is regenerated from the host files instead of edited by hand; never commit it.
- Indonesian audio paths: the local FunASR models (SenseVoiceSmall, Paraformer, Fun-ASR-Nano) are zh/en/yue/ja/ko only and return gibberish for Indonesian, so the `asr` slot uses the `google-asr` provider, which posts inline WAV to `generateContent` and reads both `audioTranscription` and plain `text` parts. VoxCPM2 TTS is fine in Indonesian (a Gemini round-trip transcribed its sample exactly).
- Gemini free-tier quotas on the current key (RPM/RPD): `gemini-3.6-flash` and `gemini-3.8-flash` 5/20, `gemini-3.5-flash-lite` and `gemini-3.1-flash-lite` 15/500, `gemini-3.5-transcribe` 3/25, all TTS 3/10, every Nano Banana/image model **0** (free tier excludes image output), Gemini 3+ search grounding 0. Therefore `llm`/`agent` default to `gemini-3.5-flash-lite` (500 RPD) and `asr` to `gemini-3.1-flash-lite` (500 RPD, verified byte-identical to the dedicated transcribe model on the Indonesian sample); 3.6/3.8 stay selectable for one-off quality runs. Image stays on local ComfyUI/SDXL because Gemini image calls return `429 ... limit: 0`.
- A narration batch is the one case where `PARALLEL_SCENE_CONCURRENCY=5` queues behind a single GPU: VoxCPM serves requests serially, so a five-clip batch spans ~8-40 s and clip five would die under the old 30 s `narrationClip` step deadline (“Gagal sintesis suara” in the UI). `STEP_DEADLINES_MS.narrationClip` is therefore 120 s, matching `TTS_REQUEST_TIMEOUT_MS`; raise it, do not parallelise the GPU.
- The python-api VoxCPM backend has no server-side voice registry (`POST /v1/audio/voices` is vllm-omni only) and synthesizes a fresh timbre on every call when given only a text voice prompt, so a course would narrate as five different teachers. `lib/server/generation/run/narrator-reference.ts` bootstraps one short reference clip per narrator voice design (cached in-process, deduped per voice) and the narration step threads it as inline `reference_audio` every clip; the adapter then sends the raw text instead of the `(design)` prefix. Cloning matches timbre, language-agnostic; Voices still need a matching `voiceDesign`/persona (id or en sample) for a gendered, consistent narrator.
- Discussion agents ride the same seam on the client (`useDiscussionTTS` → `resolveAgentVoiceOptions` → `getVoxCPMProviderOptions`). The browser cannot register a voice against python-api, so the first line for a voice design fires one inline bootstrap through `/api/generate/tts` (cached per design in memory) and every later line pins that clip as `reference_audio`; the vllm-omni registration path is untouched. If the bootstrap fails, the inline voice prompt still works — just not stable across lines.
- Avatar artwork gender is not guessable from a path; `lib/audio/avatar-gender.ts` maps the 12 avatars the profile step advertises, the prompt lists each with `gender`, and `alignVoiceDesignGenderToAvatar` rewrites the model's `voiceDesign` (gender word swap: male↔female, pria↔wanita, 男↔女) to the avatar chosen for that agent before the roster is saved. So a female-figure avatar narrates and speaks in the discussion in a woman's voice, matching name/persona/timbre.
- `install.sh --colab` no longer runs its heavy steps serially: step 4g releases `scripts/gpu-services.sh` (SDXL download ~6.9 GB + pip) into the background and `bun install` runs alongside it, the DB schema bootstrap overlaps the production build, the two dependency verifications run concurrently, and `scripts/build-packages.mjs` builds 3 workspace packages at once on a ≥4 vCPU/12 GB host (2 on a 2-vCPU runtime). `terapkan_layanan_gpu()` still waits for the health checks before 4a/4b write endpoints, because `NEXT_PUBLIC_*` is baked during the build. When adding a step, ask whether it depends on `node_modules`/the GPU result before serialising it; the background helpers (`GPU_SYNC_*`, `BOOTSTRAP_*`) print their log when joined and are killed by the exit trap.
- Maximize the RAM a memory-heavy Node task may use instead of leaving Node's default heap. The Next.js production build type-checks a large module graph and can exceed the default ~2 GB limit, failing with `FATAL ERROR: Reached heap limit`.
- Check `free -h` first, then set `NODE_OPTIONS` below the available RAM so the OS keeps headroom. On the 12 GB Colab host, use:
  ```bash
  NODE_OPTIONS="--max-old-space-size=8192" bun run build
  ```
- Use the same setting for other heavy runs (large test suites, type checks). Do not run several memory-heavy tasks at once.
- `install.sh` sizes the build heap as `min(8192, RAM - 2048)` MB, so a 12 GB Colab host gets the 8192 MB above instead of the old 3072 MB cap. On Colab's 2 vCPU a Turbopack production build (`--build`/`--with-pm2`/`--colab`) dominates a cold run (~10-15 min) and Bun cannot speed it up; the installer's wins are building workspace packages two at a time and running model discovery alongside the build.
- `--colab` means **production + all application feature flags ON**: it sets `WITH_BUILD=1` and `WITH_PM2=1` (standalone build + PM2), force-writes the feature flags from `deploy-dev-node-native-full-features.ipynb` before the build (production bakes `NEXT_PUBLIC_*` at build time). Docker/Compose, SearXNG and Lemonade are always left out. On a host **without** an NVIDIA GPU it blanks the local provider endpoints (`RENDER_SERVICE_URL`, Ollama, FunASR, VoxCPM, ComfyUI); on a host **with** one it runs the GPU step instead (see “Local GPU model services”) and only writes endpoints that passed a health check. `--dev` is rejected together with `--colab`/`--with-pm2` (same port); `--no-start` builds and syncs standalone assets without launching PM2 or the GPU services. When switching a running `--dev` host to production, the installer stops the detached dev server (process group in `data/dev-server.pid`) and warns if the port is still busy, otherwise PM2 fails to bind. Do not add local providers back into the preset without an explicit opt-in (`--with-gpu` or GPU detection).
- Bun is downloaded from the npm registry (`@oven/bun-linux-<arch>`, override with `BUN_NPM_REGISTRY`) before the official `bun.sh` installer. The official installer fetches from GitHub Releases, which intermittently answers `504` on Colab and used to abort `--colab` at `bun: instalasi`; both paths now go through `unduh_retry`. To test the Bun step without a full install, extract `unduh_retry`/`pasang_bun_npm` into a scratch script with a temporary `BUN_INSTALL_PREFIX`.
- Antigravity is the local `agy` CLI (`lib/ai/antigravity-cli.ts`, transport api `antigravity-sdk`), never a Python bridge. The installer installs `agy` and refreshes `ANTIGRAVITY_MODELS` from `agy models` (login-aware, like the Codex/OpenCode discovery); there is no `.venv-antigravity` and no `google-antigravity` pip package anywhere.
- All workbench auth UI copy lives in `workspace.auth.*` and `workspace.modelPicker.*` in `lib/i18n/locales/<locale>.json` (13 locales, kept in sync by the i18n script); never hardcode Indonesian/English strings in the panels.
- Model-selector tests must pin `OPENCODE_ACTIVE_MODEL_FILE` to a scratch path: a local `data/agent-driver-model.json` would otherwise leak into every resolution path and fail unrelated suites.
- `install.sh` ships Gemini as the only default LLM path (`google` preset, `GOOGLE_API_KEY`/`GOOGLE_MODELS`); the CLI transports are opt-in (`--with-opencode`, `--with-codex`, `--with-antigravity`) and when off there is no agy install, no `opencode models`/`codex app-server`/`agy models` discovery, and no provider block written. Slots move off `opencode:`/`codex:`/`antigravity:` to `google:` when Gemini is on; existing provider blocks are left untouched. Free-tier quota drives the ordering: `gemini-3.8-flash` and `gemini-3.6-flash` are 20 RPD, `*-flash-lite` 500 RPD — and on this host 3.8 answers with 503/timeout (>90 s) while 3.6 returns in ~2 s, so llm/agent use 3.6 with a 3.5-flash-lite fallback and classroom uses 3.5-flash-lite. Check a doubtful model with a direct `generativelanguage.googleapis.com/v1beta/models/<id>:generateContent` call before making it the slot default.
- This app deploys `.next/standalone` through PM2. `next build` does not copy the client assets into it, so after every build sync them before restarting, or the HTML loads but every `/_next/static/*` request is a 404 and the page shows "This page couldn't load":
  ```bash
  rm -rf .next/standalone/.next/static .next/standalone/public
  cp -a .next/static .next/standalone/.next/static
  cp -a public .next/standalone/public
  pm2 restart kelaska
  ```
  `install.sh --with-pm2` performs the same sync automatically.
- Standalone learning diagrams at the repo root (for example `perjalanan-bahan-menuju-daun.html`) are dependency-free HTML/SVG. Validate both the desktop and mobile layouts with Playwright at 1440 px and 390 px; the diagram switches to a compact stacked layout when the canvas is narrower than 560 px. A fresh host/test container has no Playwright browser: run `./node_modules/.bin/playwright install chromium --only-shell` and `./node_modules/.bin/playwright install-deps chromium` before a screenshot run, or Chromium exits 127 on missing `libatk-1.0.so.0`. The access-code gate does not block page loads, but API calls need a cookie: `POST /api/access-code/verify {code}` inside a Playwright request context (code read from `.env.local`, never printed).
- Cycle diagrams (`siklus-hidup-hewan.html`) add loop-back edges (dewasa → telur) as hand-authored cubic curves in a per-layout `paths` map with halo-stroked plain-text labels, because a rect-clipped straight segment would run through the cycle's own nodes; only forward edges use the computed rect-border intersection. When a layout hides an edge (mobile stacks nodes, so two conclusion edges would cross a whole column), list it in that layout's `hideEdges`. To assert label/pill geometry with Playwright, translate group `transform` back into root SVG coordinates before comparing `getBBox()` against the viewBox — `getBBox()` ignores transforms and reports every translated pill as "outside the viewBox" otherwise.
- Standalone simulation widgets keep the control panel stacked above the canvas below 900 px (`max-height: 40vh; overflow-y: auto`) and give the canvas at least 300 px; gradient or data state must still be visible without scrolling the page. A restart pulse animates `box-shadow`, never `transform`: an element with a perpetual transform animation never becomes “stable”, so Playwright clicks time out.
- Simulation reset must clear every animation-owned value (time, measured rate, O₂, history, bubbles, growth, animation clock), not just the sliders. Keyboard handling must not skip every focused button: let Space use the button's native activation there, but still map `R` to reset, or reset silently stops working after the first click.
- The host's untracked `openmaic.yml` (written by install.sh) is read by model/slot resolution at runtime, so provider-config tests like `tests/agent-runtime/owner-extraction-options.test.ts` fail on the live host while the same suite passes in a clean worktree. When a merge or push looks red, first re-run the failing file in `git worktree` off `origin/<branch>` and with `openmaic.yml` copied into and out of it before blaming the change; CI is unaffected.
- A live database can record `owner-material` migration 6 while `owner_material.asset_id` is missing (restored or externally migrated database). The extractor then logs `[MaterialExtraction] extraction scan failed: column "asset_id" does not exist` on every scan and the material library fails. Migration 6 is already recorded, so it is skipped; repair operationally with `ALTER TABLE owner_material ADD COLUMN IF NOT EXISTS asset_id TEXT;` (nullable, exactly migration 6's DDL), then confirm `pm2 logs kelaska` stops logging the error.
- `lib/i18n/locales/id-ID.json` is fork-owned (upstream ships neither it nor its extra keys), so every upstream locale addition must be mirrored there by hand or `tsc --noEmit` fails on the `LOADERS: Record<Locale, ...>` map in `material-model-copy.ts` even though `check-i18n-keys` only flags extra/missing keys and does not stop that build gate.

## Local GPU model services

- `scripts/gpu-services.sh` owns the GPU stack (Ollama, ComfyUI, FunASR, VoxCPM2). `install.sh --colab` runs it automatically when `nvidia-smi` lists a device, `--with-gpu` forces it, `--no-gpu` skips it. `--colab` passes `--skip ollama`: the local LLM is not installed there because chat runs on Gemini and its weights would compete for VRAM with the media models; only an explicit `--with-gpu` (`WITH_GPU_LLM=1`) adds Ollama, its provider block and the `agent.title` slot. Models live in `--gpu-dir` (default `/opt/gpu-models`), never in the repo; services are detached (PID files in `<dir>/pids`, logs in `<dir>/logs`), and the script rewrites `<dir>/gpu-services.env`. Only a service whose health check answered is written to `.env.local`/`openmaic.yml`, so a dead endpoint never reaches the app.
- Service ports: Ollama 11434, FunASR 8000, VoxCPM 8001, ComfyUI 8188. With two GPUs, **ComfyUI alone** uses GPU 0 and Ollama+FunASR+VoxCPM use GPU 1: SDXL holds ~7 GiB at idle and peaks ~10.4 GiB while sampling, so a resident Ollama model (~4 GiB for `llama3.2:3b`) on the same card would sit at ~14.7 GiB of 15 GiB and OOM. Restart after a reboot with `./scripts/gpu-services.sh` (idempotent) or `--status` to inspect.
- Ollama is a real chat provider, not just a picker entry, but it is opt-in: only `install.sh --with-gpu` (never plain `--colab`) fills the config-only `agent.title` slot with `ollama:<model>`, so conversation titles run on the GPU and cost no cloud quota. `gpu-services.sh` starts it with `OLLAMA_NUM_PARALLEL=4`, `OLLAMA_MAX_LOADED_MODELS=1`, `OLLAMA_KEEP_ALIVE=10m` and sends one warm-up completion after the pull — the first load of a never-used model reads 4 GB from disk and took >2 min here, which overruns the title task's 10 s budget, while a cache-warm reload takes ~4.5 s. Without an Ollama provider the slot follows `agent` (Gemini). Measured peaks on 2× T4: GPU 0 10.4 GiB/100 % during image generation, GPU 1 10.9 GiB/100 % during TTS, and both can reach 100 % at once because the media slots live on different cards. On a 2× T4 host also set `OPENMAIC_AGENT_TTS_CONCURRENCY=2` (default 1) and `OPENMAIC_GENERATION_RUN_MAX_CONCURRENT=4`, or VoxCPM idles across a whole narration batch.
- A skipped service keeps its previous `GPU_*_STATUS` in `<dir>/gpu-services.env`, so `install.sh` also ignores and unsets `GPU_OLLAMA_*` when `WITH_GPU_LLM=0`; a still-running Ollama from an earlier run is only warned about (the script never stops skipped services), so free the VRAM by hand before ComfyUI needs it.
- VoxCPM2 must be wired through `openmaic.yml` (`preset: voxcpm-tts`, `options.backend: python-api`, `baseUrl: http://127.0.0.1:8001`). The legacy `TTS_VOXCPM_BASE_URL` cannot select the backend (it always means `vllm-omni`), so the installer never sets it. `scripts/gpu_servers/voxcpm_openai_server.py` speaks the adapter's `POST /tts/upload` contract; `vllm-omni` is not installed on T4 hosts.
- ComfyUI is a client-only provider: `IMAGE_COMFYUI_ENABLED` can only *disable* it, so the workflow file is the real switch. Ship an API-format workflow in `public/comfyui-*.json` with nodes titled `Input Prompt`, `Width`, `Height`, `KSampler` (see `comfyui-setup-instructions.md`); `public/comfyui-sdxl.json` is the SDXL baseline. Remember to copy it into `.next/standalone/public` alongside the other assets or the server-side adapter cannot find it.
- `funasr_openai_server.py` and `voxcpm_openai_server.py` read `FUNASR_DEVICE`/`VOXCPM_DEVICE` (default `cuda:0`, CPU fallback when CUDA is unavailable) and preload the model, so a `/health` hit after `install.sh` proves the CUDA path works. Kaggle images have no `ensurepip`, so `gpu-services.sh` creates venvs with `uv` first and only falls back to `python3 -m venv`.
- The Ollama installer needs `zstd`; the GPU step installs it when missing, otherwise the download aborts before any model is pulled. A T4 host also has to stay on `optimize=false` for VoxCPM (`torch.compile` on sm75 is not worth the first-request stall).
- To verify the GPU path, round-trip **English** text: VoxCPM2 checkpoints declare `dtype: bfloat16`, which still transcribes accurately on a T4 (sm75) with torch 2.11/cu130, so no dtype override is needed — but SenseVoiceSmall only knows zh/en/yue/ja/ko, so Indonesian output always comes back as gibberish. Judge a smoke test by the WAV (48 kHz, plausible duration) plus an English round-trip, not by transcribing the Indonesian smoke sentence.

## Persistence and storage

- Agent-created content must not land in the project folder. Course documents and jobs go to PostgreSQL; generated images, video, posters and narration go through `storeGeneratedAsset` (asset pool: PostgreSQL or the configured S3/HF S3 byte store); uploaded source files and extraction results go through `getMaterialByteStore`, which uses Hugging Face S3 when `HF_S3_*` is set. `data/` is left for the one-time legacy classroom import, local usage records and the global driver-model default only.
- `HF_S3_*` feeds two layers from one bucket: the `huggingface-s3` asset store (content-hash keys, registered in `instrumentation.node.ts`) and `lib/server/materials/s3-bytes.ts` (keys under `materials/…`). Keep `ASSET_S3_BUCKET` unset beside it. The namespaces cannot collide, so do not add a separate prefix or bucket unless the existing keys are migrated.
- Agent narration used to be written to `data/classrooms/<stage>/media` and referenced as `/api/classroom-media/...`; it now stores an `ast_` asset id in `audioId` (no legacy `audioUrl`). Playback and export resolve allocated ids pool-first, and the timeline's `audioExists` probes the pool after a local miss, so do not reintroduce a local-disk fallback for narration.

- The agent login entry (OpenCode Console / Antigravity / Codex) lives in the Pro Workbench model picker's footer action, not in the chat header. `WorkbenchAuthDialog` is controlled (`open`/`onOpenChange`/`onStatusChange`) and mounted by `WorkbenchModelPicker`; classic `components/settings/model-picker.tsx` renders the same popover without it via the optional `footerAction` prop.

- The model popover caps its whole content at `--radix-popover-content-available-height` (flex column, list `min-h-0 max-h-[320px] overflow-y-auto`), not just the list. The search row and footer action are fixed height, so a list-only cap still overflows the viewport and clips the search field when the trigger sits near an edge.
- The picker shows only models the signed-in account can actually use: live `opencode models` (login-aware; `OPENCODE_MODELS`/`OPENCODE_GO_MODELS` act as an optional operator allowlist intersected with the live list), Codex `model/list` gated on `codex login status`, and `agy models` (Antigravity also gated on `antigravityCliAuthStatus().authenticated`; a stale cache must never survive a logout). - Per-conversation driver models: `agent_sessions.driver_model` (migration v4, `@openmaic/storage` >= 0.39.4) carries `{model, api?, thinking?}`. The chat-header picker writes it via `POST /api/agent/models {sessionId}` and reads it via `GET /api/agent/models?sessionId=`, so old conversations never switch models when a new one is created; the home picker still writes the global default (`data/agent-driver-model.json`) that seeds new conversations. The runner resolves slot → session override (validated against live discovery) → global default.
- The hero lockup (`BrandLogo size="lg"`, shared by `/` and the Pro Workspace) sizes the two government logos by **height**. Their PNGs have different aspect ratios (`logo-kemendikdasmen.png` 300×240, `logo-dprd.png` 251×240), so a fixed *width* renders DPRD taller and makes the pair look lopsided; the mobile override in `app/home-mobile.css` is height-based (`height: 44px; width: auto`) for the same reason. The Pro badge offsets (`mt-[9px] md:mt-[11px]`) track the wordmark size and exist twice — `app/page.tsx` and `components/workbench/workspace/WorkspaceHome.tsx` — so changing `lg` means changing both.

## Code Review Rules

### Severity

- P1 is only for problems that produce wrong behavior at runtime: user-visible breakage, data loss, data exposed across owners, an authentication or access-control bypass, a storage migration that fails on an existing database, a published package that ships broken, or a leaked secret.
- Inaccuracies that only affect documentation, comments, skill text or the PR description are at most P2. Do not report wording that cannot cause a failure or a wrong action.
- Do not report pure style, naming or readability preferences.

### Context and scope

- Read the PR description before reviewing. Do not raise an issue the description already accounts for (handled in another PR or issue, or a deliberate trade-off with its reason) unless you can show that explanation is wrong.
- Do not raise again an issue whose thread already has a reply explaining why it stays.
- When reviewing new commits, report only problems introduced or exposed by the new or changed code. Do not add edge cases on code the push did not touch.
- Do not report pre-existing behavior that the PR does not change.
- When a fix needs changes outside the PR (callers, documentation, other packages), name the file paths.

### Focus areas

- Owner scoping: reads and writes of courses, sessions, materials and settings stay within the requesting owner.
- Storage schema changes (`packages/@openmaic/storage`): compatible with databases that are already deployed.
- Published packages (`packages/@openmaic/*`): a change to published behavior comes with the version bump described in [Changing a Published Package](CONTRIBUTING.md#changing-a-published-package).
- Provider neutrality: shared layers do not hard-code a specific model or service vendor; vendor-specific behavior stays in that provider's module.
- Server-side requests to user-supplied URLs go through the existing URL guard.
