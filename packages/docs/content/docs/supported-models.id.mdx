Halaman ini mencantumkan penyedia dan model yang terpasang di edisi Kelas Kecerdasan Artifisial sumber terbuka. Di [`openmaic.yml`](./configuration.mdx) sebuah penyedia menamai salah satunya sebagai `preset`-nya, dan pengaturan model aplikasi web menawarkan katalog yang sama. Ketersediaan juga bergantung pada akun penyedia, wilayah, dan konfigurasi server, serta daftar `models` sebuah penyedia dapat mempersempit apa yang ditawarkan pengaturan model.

## Preset

Preset adalah templat penyedia bawaan: vendor mana, endpoint mana, dan kapabilitas mana yang dicakup satu akun. Setiap penyedia di `openmaic.yml` atau di pengaturan model menamai sebuah preset.

**Preset satu kapabilitas** memiliki ID penyedia dari tabel di bawah, satu per kapabilitas: `openai` adalah chat OpenAI, sedangkan gambar, ucapan, dan transkripsi OpenAI adalah `openai-image`, `openai-tts`, dan `openai-whisper`. Tiga ID berbeda dari ID registri karena preset lain sudah memakainya: pencarian web MiniMax adalah `minimax-search`, pencarian web Doubao adalah `doubao-search`, dan pembuatan gambar Lemonade adalah `lemonade-image`.

**Preset paket token** mencakup beberapa kapabilitas dengan satu key, masing-masing pada endpoint paket itu sendiri. Menghubungkan salah satunya di **Pengaturan → Paket Token** juga mengisi slot yang direkomendasikan paket tersebut dan masih belum ditetapkan.

| Preset | Paket | Mencakup |
| --- | --- | --- |
| `minimax` | MiniMax | Chat, gambar, video, TTS, pencarian web |
| `tokendance` | TokenDance | Chat, gambar, video, TTS, pencarian web |
| `volcengine-ark` | Volcengine Ark Agent Plan | Chat, gambar, video, TTS, pencarian web |
| `kimi-coding-plan` | Kimi Coding Plan | Chat, pencarian web, pengambilan web |
| `deepseek-token-plan` | DeepSeek | Chat, pencarian web, pengambilan web |

Menghubungkan Kimi Coding Plan di **Pengaturan → Paket Token** merekomendasikan chat, pencarian web, dan pengambilan web sekaligus, menggunakan key Coding Plan dan `https://api.kimi.com/coding/v1`. Jika pengambilan web hanya menggunakan bawaan implisit, menghubungkan akan menetapkan Kimi secara langsung tanpa konflik, bahkan ketika pengaturan saat ini dipertahankan. Pilihan workspace eksplisit (termasuk `null`) dan pembaca non-bawaan yang dikonfigurasi deployment atau `null` menggunakan pilihan konflik yang ada. Memutuskan koneksi menghapus penetapan paket dan memulihkan bawaan server (pembaca bawaan bila tidak ada pembaca yang dikonfigurasi); ini tidak memulihkan pilihan workspace eksplisit sebelumnya. Slot yang terkunci tetap tidak berubah. Paket yang tidak mendeklarasikan pengambilan web membiarkannya tidak tersentuh.

Menghubungkan DeepSeek di **Pengaturan → Paket Token** merekomendasikan chat (`deepseek-flash` secara bawaan), pencarian web, dan pengambilan web sekaligus, menggunakan satu API key DeepSeek dan `https://api.deepseek.com/v1`. Ini adalah akun dan endpoint bayar sesuai pemakaian yang sama dengan preset `deepseek`; paket ini memakai preset `deepseek-token-plan` sendiri agar memutuskan koneksinya hanya menghapus penyedia dan penetapan paket tersebut, dan membiarkan penyedia `deepseek` terpisah tetap tidak berubah.

Wizard pertama kali membiarkan pengambilan web pada pembaca bawaan; hanya menghubungkan paket melalui halaman pengaturan Paket Token yang menerapkan rekomendasi pengambilan webnya.

`openai-compatible` menghubungkan server chat apa pun yang kompatibel dengan OpenAI: ia memerlukan `baseUrl`, dan daftar `models`-nya adalah yang ditawarkan pengaturan model.

## Model LLM

Di `openmaic.yml` sebuah slot chat menamai `<provider id>:<model id>`, di mana ID penyedia adalah yang Anda deklarasikan di bawah `providers`, misalnya `openai:gpt-5.6`, `qwen:qwen3.7-plus`, atau `ollama:llama3.3` bila ID penyedia cocok dengan ID preset.

CrowLLM sendiri tidak menerbitkan batas konteks, output, atau visi untuk ID mana pun, sehingga baris `crowllm` bawaan mencerminkan batas model pihak pertama yang mendasarinya (ditampilkan di panel pengaturan di samping setiap model sebagai perkiraan); reasoning dikirim sebagai ID `*-thinking` terpisah alih-alih sebagai tombol permintaan.

Google mencantumkan **17 November 2026** sebagai [tanggal penghentian paling awal](https://ai.google.dev/gemini-api/docs/deprecations) untuk tiga model pratinjau di atas. Pilih model 3.8 sebelum model tersebut pensiun; untuk kredensial yang dikelola deployment, perbarui juga slot `tts` atau allowlist `models` penyedia di `openmaic.yml`. Respons WAV Gemini 3.8 dipertahankan; respons PCM yang lebih lama tetap dikonversi ke WAV untuk pemutaran.

### Suara hasil kloning Qwen

Integrasi ini menggunakan API sintesis HTTP non-real-time CosyVoice. Wilayah terdokumentasinya adalah **Beijing**; gunakan endpoint dan API key Beijing. Singapura mendukung pendaftaran untuk `cosyvoice-v3-plus` dan `cosyvoice-v3-flash`, tetapi [tabel dukungan sintesis non-real-time](https://www.alibabacloud.com/help/en/model-studio/non-realtime-tts-user-guide#supported-models) tidak mencantumkan CosyVoice di Singapura. Memilih salah satu model tersebut saja tidak membuat integrasi ini mendukung pemutaran di Singapura. Lihat [wilayah pendaftaran](https://www.alibabacloud.com/help/en/model-studio/voice-cloning-user-guide#supported-models) dan [CosyVoice HTTP API](https://www.alibabacloud.com/help/en/model-studio/cosyvoice-tts-http-api).

Target bawaannya adalah `cosyvoice-v3.5-plus`. `TTS_QWEN_VOICE_CLONE_MODEL` berlaku untuk pendaftaran dan pemutaran yang dikelola server maupun BYOK; nilai kosong atau nilai pensiun persis `qwen3-tts-vc-2026-01-22` menggunakan bawaan tersebut. Override eksplisit lainnya dipertahankan dan tetap memerlukan otorisasi model. API key tidak digunakan untuk menyimpulkan wilayah, dan override tidak mengubah transport sintesis.

Deployment terkelola harus mempertahankan `qwen3-tts-flash` bersama target kloning, misalnya `TTS_QWEN_MODELS=qwen3-tts-flash,cosyvoice-v3.5-plus`, atau mencantumkan keduanya di allowlist `models` penyedia di `openmaic.yml`. Menetapkan hanya target kloning akan menggantikan otorisasi model katalog implisit dan menyebabkan suara katalog mengembalikan HTTP 403. Pertahankan juga otorisasi untuk model lain yang sudah Anda gunakan.

Pendaftaran suara menggunakan sampel audio dan tidak memerlukan transkrip.

Profil lama yang tersimpan dan sampel referensinya dipertahankan, tetapi tidak ada migrasi sampel sekali klik. Untuk membuat ulang suara yang tidak kompatibel, unggah lagi audio referensi aslinya melalui pengaturan suara dan buat kloning baru. Gunakan sampel bersih dengan setidaknya lima detik ucapan; sampel lama yang lebih pendek dari lima detik harus diganti dengan rekaman yang lebih panjang. Menyimpan sampel dalam profil tidak secara otomatis mendaftarkannya ulang.

### Pencarian dan pengambilan web DeepSeek

Preset `deepseek` berbagi `DEEPSEEK_API_KEY` dan basis API di seluruh chat, pencarian web, serta ekstraksi Markdown terkelola. Pencarian menggunakan `POST /v1/tools/search`, mengembalikan hingga 50 hasil, memotong kueri hingga 128 titik kode Unicode, dan menggunakan `summary` dengan `snippet` sebagai cadangan. Pengambilan menggunakan `POST /v1/tools/fetch` dan membaca `content` serta `title` opsional yang tidak kosong.

Pada konfigurasi lama, aktifkan dengan `WEB_SEARCH_DEEPSEEK_ENABLED=true` atau entri eksplisit `web-search.deepseek` di `server-providers.yml`. Kredensial chat saja tidak pernah mengaktifkan pencarian atau menggantikan bawaan pencarian lain. `WEB_SEARCH_DEEPSEEK_ENABLED=false` memaksa penonaktifan pencarian. Bila `openmaic.yml` ada, variabel lama tidak dapat menetapkan slot: deklarasikan penyedia secara eksplisit dan tetapkan `webSearch` dan/atau `webFetch`.

Basis API bawaan adalah `https://api.deepseek.com/v1`. Pada `api.deepseek.com`, setiap jalur basis (termasuk `/beta`) dinormalisasi ke `/v1` sebelum `/tools/search` atau `/tools/fetch` ditambahkan. Basis gateway kustom mempertahankan prefiks jalur yang dikonfigurasi; akar kosong mendapat `/v1` terlebih dahulu. Endpoint kustom termasuk dalam konfigurasi deployment, sementara override klien dan workspace tetap dibatasi pada endpoint resmi. Pembaca pengambilan bawaan tetap `builtin`. Lihat [harga resmi DeepSeek](https://api-docs.deepseek.com/quick_start/pricing) untuk biaya permintaan saat ini. Permintaan yang gagal dan pencarian tanpa hasil tidak ditagih.

```yaml
providers:
  deepseek:
    preset: deepseek
    apiKey: ${DEEPSEEK_API_KEY}
    baseUrl: https://api.deepseek.com/v1
slots:
  webSearch: deepseek
  webFetch: deepseek
```

### Pencarian web Kimi

Preset `kimi` (Moonshot Open Platform) dan preset `kimi-coding-plan` sama-sama melayani chat dan pencarian web dengan satu API key dan base URL. Tetapkan `webSearch` ke penyedia yang sama dengan yang dipakai untuk chat; tidak diperlukan key kedua atau model pencarian.

Basis Open Platform `https://api.moonshot.cn/v1` dan `https://api.moonshot.ai/v1` menggunakan `/tools/search_pro`; konten hasil menggabungkan potongan halaman, dengan snippet sebagai cadangan. Basis Coding Plan `https://api.kimi.com/coding/v1` dan `https://api.kimi.ai/coding/v1` menggunakan `/search` dengan perayapan halaman diaktifkan; konten hasil lebih mengutamakan konten halaman daripada snippet. Setiap permintaan mengembalikan paling banyak 20 hasil.

Kredensial chat saja tidak mengaktifkan pencarian pada konfigurasi lama. Aktifkan dengan `WEB_SEARCH_KIMI_ENABLED=true` atau entri eksplisit `web-search.kimi` di `server-providers.yml`. Di `openmaic.yml`, tetapkan slot `webSearch` secara eksplisit. Wizard merekomendasikan pencarian hanya untuk basis akun resmi.

Pemilihan endpoint mengikuti jalur basis: setelah garis miring di akhir dihapus, jalur yang berakhiran `/coding/v1` menggunakan `/search`; setiap basis lain menggunakan `/tools/search_pro`. Proxy kustom yang dikonfigurasi di `openmaic.yml` harus mempertahankan tata letak jalur tersebut.

Bila `openmaic.yml` ada, deklarasikan `providers.<id>: { preset: kimi }` dan tetapkan `slots.webSearch: <id>`; variabel lama `WEB_SEARCH_KIMI_ENABLED` tidak dapat menetapkan slot tersebut.

## Pengambilan web

Slot `webFetch` secara bawaan memakai pembaca `builtin` tanpa key (Readability dan Turndown; PDF tetap menggunakan `document`). Baik `kimi` maupun `kimi-coding-plan` menggunakan ulang key dan basis API penyedianya untuk ekstraksi terkelola. Moonshot Open Platform menggunakan `/tools/fetch`, sedangkan Coding Plan menggunakan `/fetch`. `firecrawl` menggunakan key Firecrawl-nya sendiri, yang dibagi dengan pencarian web Firecrawl, dan memanggil `/v2/scrape`. Tidak ada fallback. Pilih pembaca di Layanan Model / Konfigurasi Model Kursus atau tetapkan `slots.webFetch` di `openmaic.yml`. Key Kimi dibagi dengan chat. Semua pembaca mempertahankan pemeriksaan sesi lokal dan alamat publik serta hasil yang tidak tepercaya.

DeepSeek juga menawarkan ekstraksi Markdown terkelola melalui preset `deepseek`, dengan menggunakan ulang key chat dan basis API. Tetapkan `webFetch` secara eksplisit seperti ditunjukkan di atas. Ini menggunakan `/v1/tools/fetch`; basis gateway deployment yang eksplisit dipertahankan. Ini mempertahankan tenggat transport yang sama dan satu percobaan ulang kesalahan transport yang sama seperti Kimi, tanpa mencoba ulang kesalahan HTTP atau respons yang tidak valid.
